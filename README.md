# LearnDNA — Web Version

This is the **website version** of the LearnDNA Java project — same logic (Knowledge Graph, topological sort, rule-based recommendation engine, mastery scoring, revision planner), now running directly in the browser. No Java compile, classpath or IDE setup needed.

## How to run (2 ways)

**Simplest:** double-click `index.html` — it opens in the browser and the whole app works.

**Recommended (for demos / viva):** open the folder in VS Code or any editor, start a local server, then open `http://localhost:8000`:
```
python3 -m http.server 8000
```
(A local server is more reliable because secure password hashing and fonts need it, but double-clicking works for most features.)

No npm install, no backend, no database setup — everything is plain HTML/CSS/JS, and data is saved in the browser's `localStorage` (create a student or sign in again with the same email to get your progress back).

## Flow

1. **Sign in / Create account** — name, email and a strong password
2. **Pick a course** — Java, C, C++, Python, DSA, DBMS or OOP
3. **Self-assessment** — mark each topic "Don't know / Somewhat / Confident"; this builds your **Knowledge DNA**
4. **Dashboard** — overall DNA score, weak areas, recommended next topics
5. **Knowledge Graph Explorer** — all topics and their prerequisites as a visual graph
6. **Roadmap** — an ordered learning path generated by goal-backward planning (topological sort)
7. **Topic page** — complete resources to raise mastery
8. **Quiz** — round-based MCQs; mastery updates on submit
9. **Revision planner** — flags topics not revised for 3+ days
10. **Analytics** — average mastery per domain

## Mapping from the Java project (for viva)

The web version follows the same class names and logic as the original Java project, so it is easy to explain:

| Java class | Web equivalent |
|---|---|
| `learndna.model.Topic`, `Goal`, `Student`, `KnowledgeDNA` | `module1-data-knowledge-graph/models.js` — same fields, same methods |
| `learndna.graph.KnowledgeGraph` (BFS/DFS/Kahn's topo sort/cycle check) | `module1-data-knowledge-graph/graph.js` — line-by-line same algorithm, JS Map/Set instead of Java HashMap/HashSet |
| `learndna.engine.RuleBasedRecommendationEngine` (goal relevance + readiness + weakness + time fit scoring) | `module2-adaptive-engine-quiz/engine.js` — same scoring formula |
| `learndna.util.DataSeeder` | `module1-data-knowledge-graph/data.js` — same T1–T9 topics, same G1 goal, same prerequisite edges |
| Java Swing GUI (`MainFrame`, `DashboardPanel`, `RoadmapPanel`, `TopicExplorerPanel`, `QuizPanel`) | `module3-dashboard-roadmap-analytics/ui.js` screens — Dashboard, Roadmap, Graph Explorer, Topic page, Quiz |
| JDBC Data Access Layer | `module4-login-integration/store.js` (`localStorage` — no server/DB needed for the demo) |

This shows that the OOP design is unchanged — only the presentation and persistence layers were swapped for the web (as already noted under "Future Scope" in the documentation: *"Mobile/web version using Spring Boot + React/Android"*).

## Update v2
- **Auth:** Sign in + Create account tabs, password strength rules + live meter, show/hide, confirm password, lockout after 5 wrong tries. The password is stored in localStorage only as a **PBKDF2-SHA256 hash + salt** (the plain password never appears when you inspect storage). `module4-login-integration/auth.js`
- **Quiz:** rounds of 5 (topic + prerequisite revision questions, shuffled), new rounds keep coming until the topic is mastered (70%).

- Note: this is a frontend-only demo; in production, hashing should happen on the server.

## Update v3 — split into 4 modules (team submission)

Code is now divided into 4 independent module folders, so each team member can own and present one:

| Module | Folder | Contains | Owner focus |
|---|---|---|---|
| **1 — Data & Knowledge Graph** | `module1-data-knowledge-graph/` | `data.js` (seed subjects/topics/quiz bank), `models.js` (Student, KnowledgeDNA, Progress), `graph.js` (KnowledgeGraph — prerequisites, ready-to-learn) | Domain data & structures |
| **2 — Adaptive Engine & Quiz System** | `module2-adaptive-engine-quiz/` | `engine.js` (rule-based recommendation engine), `quiz.js` (round-based quiz runner, repeats until mastered) | Adaptive logic |
| **3 — Dashboard, Roadmap & Analytics UI** | `module3-dashboard-roadmap-analytics/` | `ui.js` — course picker + self-assessment, dashboard, roadmap, graph explorer, topic detail (+ external links/videos), revision planner, analytics | Learner-facing screens |
| **4 — Login & Integration** | `module4-login-integration/` | `auth.js` (register/login/hashing/session), `store.js` (localStorage persistence), `core.js` (global wiring, router, login screen, sidebar shell — boots the whole app) | Auth + gluing everything together |

**Load order matters** (see `index.html`): Module 1 → Module 2 → Module 3 → Module 4. Module 4 loads last because `core.js` wires Module 1's data into live Knowledge Graph objects and fires the app on `DOMContentLoaded`.

All 4 modules still run as one app — this is a source-level split for team ownership/viva, not separate deployments.

## Update v4 — Module 5: Engagement (end-sem features)

New folder `module5-engagement/` (loaded before Module 4 in `index.html`; the existing modules got only small hooks):

| Feature | Where | How it works |
|---|---|---|
| **Streaks & daily goals** | `engage.js` → `#/goals`, dashboard cards | Daily question target (3–20, default 5). Meeting it = streak day; missing a day resets it. 5-week activity heatmap. |
| **Custom goals** | `engage.js` → `#/goals` | Goals like "answer 20 questions" or "master 2 topics" auto-track from quizzes; "manual" goals have a Mark-done button. Optional deadline. |
| **XP & levels** | `engage.js` | +10 per correct answer, +20 per round, +50 per mastered topic, +25 daily bonus, +30 per goal. 100 XP = 1 level. |
| **Quiz explanations** | `tutor.js` (+ hook in `quiz.js`) | After submitting a round, every question shows right/wrong, the correct answer and an "Explain why" button. |
| **AI tutor** | `tutor.js` → `#/tutor` | Online mode if you paste an Anthropic API key (stays in your browser's localStorage). Offline mode (no key) answers from the Knowledge Graph: topic facts, prerequisites, resources, practice questions. |
| **Leaderboard & study groups** | `community.js` → `#/community` | All-time / weekly XP ranking. Create a group → share the 6-letter code → friends join. "Add 5 demo classmates" fills the board for a demo. |

Limits to mention in viva: leaderboard/groups are **per browser** (localStorage, no backend), so they work across accounts created on the same device. Quiz explanations are generated (AI) or templated (offline), not hand-written per question.
Integration points: `Student.engage` (models.js), `Engage.onQuiz()` call in `quiz.js`, 3 routes + nav items in `core.js`, `Engage.dashCard()` in `ui.js`.

## Update v7 — Module 6: Code Practice (course-wise)

New folder `module6-code-practice/` + `css/practice.css` (Module 4 got a route + nav item, Module 5 got 2 badges and assistant keywords). The page shows ONLY the challenges of the course you are currently learning, in the order of that course's roadmap (prerequisites first), one set per topic.

| Course | Challenges | Language | Runs where |
|---|---|---|---|
| Java (Backend Track) — 9 | Java Basics → OOP → Collections → Exceptions → Multithreading → SQL → JDBC → REST → Spring Boot | Java (SQL for the SQL topic) | remote compiler (Judge0) · SQLite in browser |
| C Programming — 7 | Basics, Control, Functions, Arrays & Strings, Pointers, Structures, File Handling | C | remote compiler (Judge0) |
| C++ & OOP — 7 | Basics, Classes, Constructors/Destructors, Inheritance, Polymorphism, Operator Overloading, STL | C++ | remote compiler (Judge0) |
| Python — 8 | Basics, Loops, Data Structures, Functions/Decorators, OOP, Files & Exceptions, NumPy, pandas | Python 3 | in-browser (Pyodide, CDN) |
| DSA — 18 | Arrays/Strings, Linked Lists, Stacks/Queues, Recursion, Trees, Graphs, Sorting/Searching, DP | JavaScript | in-browser Web Worker (offline) |
| DBMS — 7 | ER → tables, Set operations, Aggregates, Joins, Normalization, Transactions, Indexes | SQL | in-browser (sql.js SQLite, CDN) |
| OOP Fundamentals — 6 | Classes, Encapsulation, Constructors/lifecycle, Inheritance, Polymorphism, Abstraction | JavaScript | in-browser Web Worker (offline) |

* Files: `challenges.js` (registry + DSA), `challenges-<course>.js` (one per course), `practice.js` (engines, XP, pages).
* Every challenge = statement, starter code, hint, model solution and 4–5 test cases. The expected outputs were produced by running the model solutions in real compilers (javac, gcc, g++, python, SQLite), and every challenge was tested through the UI.
* **Scratchpad**: editor (Tab, Ctrl+Enter), editable input / test-data box, console output, ✓/✕ verdict vs the expected sample, Submit (all tests), Save Draft / Load Saved Draft, Reset, Copy, Hint, Show solution (solving after viewing it gives 25 % XP).
* **XP**: first full pass gives Easy 20 / Medium 40 / Hard 70 XP into `engage.xp` (same as quizzes) → weekly / all-time leaderboard. State: `student.engage.practice = { solved, drafts, code, peeked }`.
* **Needs internet**: Java/C/C++ call the public Judge0 server (`https://ce.judge0.com`, change it with the “⚙ Compiler server” button, e.g. a self-hosted Judge0); Python and SQL download their WebAssembly engine from a CDN once (then cached by the browser). JavaScript challenges (DSA, OOP) work fully offline. If the network is blocked, the page shows a clear message and nothing is graded.
* Adding a challenge = one object in the course's `challenges-<course>.js`; `topic` is a topic id from `data.js`, `lang` is `javascript | python | java | c | cpp | sql`. Programs read stdin (JS: global string `input`); SQL challenges use a `tpl` with `{{INPUT}}` (test-data inserts) and `{{USER}}`.
